# services/device

Lecture du lecteur Accu-Chek Guide via `/usr/local/bin/accuchek`.

- `fetch(raw_dir)` : vérifie la présence du lecteur (sysfs, vendor `173a`), lance `/usr/local/bin/accuchek --set-time` sans root (accès USB donné par la règle udev `packaging/udev/70-glucofi-accuchek.rules`), ou `GLUCOFI_ACCUCHEK_CMD`, parse le JSON, garde une copie brute. Aucun fichier de configuration : la liste des lecteurs acceptés est intégrée à accuchek. Bloquant : à appeler hors du thread GTK.
- `parse_output(text)` / `parse_file(path)` : lit la sortie d'accuchek au format 2 (objet avec `meter`, `clock`, `glucose`, `meal`, `readings`) et l'ancien tableau de mesures (imports de fichiers anciens, sans lecteur ni horloge). Un en-tête invalide est fatal (`InvalidOutput`) ; les mesures invalides sont écartées et listées, pas fatales. Chaque `Reading` porte son marqueur repas (`Reading.meal`, `contracts.Meal`), sans effet sur l'égalité : une mesure relue avec un marqueur n'est pas un doublon. `ParseResult` / `FetchResult` exposent l'identité du lecteur (`MeterInfo`, nom du modèle d'après la table de Tidepool), l'horloge (`MeterClock` : écart lecteur - PC, action d'accuchek), les compteurs annoncés / reçus (`SegmentCount`), les marqueurs orphelins et `warnings` (textes à afficher : lecture incomplète, marqueurs orphelins, horloge à plus de 5 min non corrigée, mise à l'heure refusée). Les lectures hors échelle du lecteur sont gardées (`"range":"high"` = HI codé 601 mg/dL, `"range":"low"` = LO codé 9 mg/dL, voir `Reading.off_scale`) ; une mesure normale avec un `status` non nul est écartée avec son motif (`statut 0x....`), journalisé à l'import.
- Erreurs, avec un message affichable qui reprend la raison donnée par accuchek : code 2 `DeviceNotConnected`, code 3 `DeviceAccessDenied`, code 4 `DeviceReadFailed`, code 5 `DeviceProtocolError` (sous-classe de `DeviceReadFailed`), code 6 `DeviceReadFailed` (accuchek n'a pas pu écrire le JSON : disque plein, pipe cassé), JSON illisible `InvalidOutput`. Codes : `contracts.AccuchekExit`, alignés sur `ExitCode` de `accuchek-src/session.h` (vérifié par `ExitCodeContractTest`). Un lecteur vide donne zéro mesure, sans erreur.
- `--set-time` : accuchek remet le lecteur à l'heure du PC si l'écart dépasse 60 s, seulement si l'horloge du PC est synchronisée (`adjtimex`) et si le lecteur se déclare réglable. Une commande explicite (`command=` ou `GLUCOFI_ACCUCHEK_CMD`) est lancée telle quelle, sans `--set-time` ajouté.
- `GLUCOFI_ACCUCHEK_CMD` remplace la commande (tests, autre binaire). Ne jamais définir `ACCUCHEK_DBG` : les logs d'accuchek partent alors sur stdout.

## Capteur FreeStyle Libre 3 (`librelinkup.py`, `llu_api.py`)

Lecture du capteur par le compte de suivi LibreLinkUp. L'API est celle de l'application Android d'Abbott, sans documentation ni garantie : si elle change, seuls `llu_api.py` (`VERSION`, en-têtes, chemins) et `librelinkup.py` sont à mettre à jour.

- `llu_api.LluClient` : client en **bibliothèque standard** (`urllib`, aucune dépendance), donc le même code tourne sur le PC et sur la tablette (Chaquopy n'a pas `pydantic-core` pour Python 3.13, donc pas `pylibrelinkup`). Connexion (`/llu/auth/login`, une redirection de région suivie, étapes imposées par le serveur nommées : conditions d'utilisation, confidentialité, e-mail), en-tête `account-id` (empreinte de l'identifiant du compte), `patients()`, `graph(patient_id)`. Il rend des dicts JSON ; `transport` est remplaçable (faux serveur `tests/fake_llu.py`).
- `load_credentials()` : `LIBRELINKUP_EMAIL`, `LIBRELINKUP_PASSWORD`, `LIBRELINKUP_REGION` (FR par défaut) dans l'environnement, sinon dans un `.env` (mêmes fichiers que la clé Gemini, jamais suivis par git). Utiliser le compte de **suivi** LibreLinkUp, jamais celui de LibreLink. `save_credentials()` écrit le `.env` du dossier de données en 0600, sans toucher aux autres lignes ; le mot de passe ne va jamais dans la base (exportée vers la tablette, fusionnable).
- `fetch_cgm(credentials, every_min=15, transport=...)` : dernière valeur + graphique du premier patient partagé, en `ParseResult` (le même type que `parse_output`, donc `Store.import_readings` l'accepte tel quel). Le capteur est décrit comme un `MeterInfo` (Abbott, FreeStyle Libre 3, numéro de série du capteur). Bloquant : hors du thread de l'interface.
- `parse_us_timestamp()` : « 10/29/2026 8:22:28 PM » lu sans `strptime`, qui ne reconnaît pas « PM » dans un processus en `fr_FR` (la langue que GTK donne au PC ; c'était l'erreur « 22 validation errors for GraphResponse »). `to_reading()` : heure locale du téléphone à la minute, valeur arrondie en mg/dL, HI = 601 et LO = 9 comme sur le lecteur, hors 10-600 mg/dL refusée. Une même mesure relue ne se duplique pas (clé `device_time, mg_dl` du magasin).
- `thin()` : le Libre 3 mesure chaque minute, le moteur de doses attend quelques mesures par jour. On garde la première mesure de chaque tranche de `every_min` minutes (`None` : toutes).
- Erreurs `LibreLinkUpError` (sous-classe de `DeviceError`) avec message affichable : identifiants refusés, aucun patient partagé, étape à faire dans l'application officielle, région inconnue, trop de demandes, réponse inattendue (l'API a peut-être changé), réseau en échec.
- Pas branché au calcul des doses ici : c'est `DosingSettings.cgm_*` (voir `services/dosing`).
